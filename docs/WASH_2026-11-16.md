# 占领晕染与省份闪动（1.18.0）

## 闪动根因

1. **易主渐变的“上一版”卡住（主因）**。`MapRenderer.recolor` 旧逻辑：`previousColors = fading ? previousColors : colors; fadeStart = now`。全图只有一个起点和一份上一版颜色；渐变（0.7 秒）未完又来新颜色时，上一版不更新、起点却重置。打仗时归属每 0.5 秒刷新一次（`GameModel.apply` 的节流），渐变永远“未完”，上一版停在这一串变化开始之前——每次有州易主，之前已变色的州都被打回更早的旧色再渐变一次，持续闪。回归测试 `ConquestWashTests.testOwnershipFadesNeverSnapBack` 用旧算法复现（亮度跳变 > 0.5）并验证新算法（< 0.1）。
2. **战场地面预算边缘进出**。`setBattleGrounds` 按兵力排名截前 10，第 10 名上下的州每步进出名单：进入“胜方铺满后淡出”，下一步又回来淡入。改为已在显示（未结束）的优先。
3. **细节硬切**。战场地面在相机比例 1.0 处硬切墨晕与笔触，缩放停在附近时边缘反复跳。改为 0.7…1.3 连续过渡。
4. **后台结果只认最新**。高倍速下归属每半秒变一次，后台重算若更慢，结果全被作废，颜色迟迟不更新后一次大跳。`MapWorkRevision` 增加按代次安装：不比屏幕上旧的结果先装上，更旧的丢弃，切视图前的颜色作废。

## 沙盘墨场（1.19.0，取代 1.18.0 的连通区域距离场与战场地面）

### 1.18.0 仍有的问题（玩家反馈：整片换色、相邻战区有的州空着）

1. 交战州的晕染整块让位给“战场地面”（按透明度互补），而战场地面是另一套按州、按营分色的效果，只显示前 10 场、战斗结束后淡出 —— 相邻几处一起打时，有的州是晕染、有的是战场地面、有的在两者交接时空着。
2. 输入只有围城（进度 > 0.5%）与攻占：军队已进入敌州但还在行军、交战、尚未开始围城时，该州没有任何颜色。
3. 区域距离场从区域边界（挨着进攻方领土处）起算：内部州的军队站在州中间、进度还低时，阈值还没推到该州，军队脚下是空的（回归测试 `testNeighbouringFrontsAreOneFieldWithoutEmptyProvinces`）。
4. 前沿以“该州覆盖面积 = 进度”推进，不管军队实际走到哪里，看起来是一整片一整片地推。

### 新做法（`Core/Sources/LieguojiCore/ConquestWash.swift`，渲染 `Render/Wash.swift`）

- 全图一张逐顶点墨场：每个地图顶点记墨主（stain）、逻辑浓度（level，0…1.6，着色在 0.5 附近过渡）与显示动画（from → to，自 start 起历时 length）。
- 输入（`WashFrame.from`）：行军（军队在敌国州，线段 = 上一步位置 → 这一步位置）、守军（本国州里有敌军或敌方围城）、围城（权威进度）、攻占（有军队或围城的易主）。
- 落墨：行军沿线段落一道墨（半径 0.55 × 尺度 × 兵力系数），沿线按投影位置延迟显现，跟上军队图标；驻留每天以军队为中心洇开；围城以进攻军为中心、半径随进度长到铺满；守军按天削弱身边的敌墨；墨每天褪 0.03。同国取浓者，别国更浓则接手。只染敌国领土。
- 攻占：先登记，等底色换成新主人时（渲染端安装颜色时发现）从已染处按距离延迟扫满，未到达处盖旧色；扫完收尾清空。视图切换直接收尾。
- 渲染：有墨格子的顶点拷贝一份缓冲（14 个数/顶点，扇形索引），只在墨场改动、易主、换视图时重建；浓度、易主扫满在着色器里按本帧时刻插值，静止时不连续重绘。
- “战场地面”（BattleGround.swift）已删除，设置项改名“战争晕染”。

## 测量

- 本地：`testRealMapCost` 在 20k 原作网格上量拓扑构建与 300 支军队每步落墨耗时。
- CI 巡览（`App/WashTour.swift`）：两路进攻军行军、围城、守军相持、攻占、拉远换视图、撤军褪墨，录 `wash.mp4`，关键帧 `40a…40g`；结果 `wash-demo.json`：主线程显示回调间隔、整帧与墨场编码耗时、GPU、上屏间隔、固定点反复变色次数、有墨格子数；另有 48 州同时打的压力段。

## 1.20.0：GPU 墨场与统一扫色（取代 1.19.0 的逐顶点墨场）

### 1.19.0 手机实测的问题
1. 墨按推演步落在格子顶点上：顶点间距（约 5 个世界单位）与墨迹宽度相近，加上纸纹噪声，墨迹一段一段、有空档；每步一次性出现，跟不上图标的连续移动。
2. 攻占后的“扫满”与州里仍在交战的敌军的墨同时作用在同一批顶点上，画面打架。
3. 反叛、割地、改朝换代没有墨晕（只有攻占有）。

### 做法
- `Render/Ink.swift`：一张世界坐标纹理（rgba16Float，预乘国色 + 浓度）。每帧先按本帧经过的推演天数整体褪色，再画：行军笔触（上一帧落墨处 → 图标此刻位置，两端齐平、首尾相接）、驻留圆点（按天洇开）、守军擦墨、围城（被围州的三角形内、以进攻军为中心、半径随进度）。合成时沿陆地三角形采样，墨色与该州主人国色相同处不显示。
- 强度公式在 Core 的 `InkPlan`（着色器同一算法），`ConquestWashTests` 在 CPU 上复算：30/60/120 帧、20–2000 单位/秒，路线中心最淡处 > 0.55、浓淡差 < 0.03；横向 1.5 个半径外不见色；驻留随天数单调扩大、暂停不长。
- `FlipSweep`：颜色真的变了且归属变了（或刚有大事的国家）的州，从攻占军队或新主人首都按距离扫色；同组共用前沿、最长 2.4 秒；政变、复辟等另有一道墨圈。
- CI 模拟器构建自 1.18.0 起失败：`CAMetalDrawable.addPresentedHandler` 模拟器 SDK 没有；工作流原先 `| tail -5` 吞掉了错误与退出码。
