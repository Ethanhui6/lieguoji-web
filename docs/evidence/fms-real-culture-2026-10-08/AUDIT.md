# WEB-03-06：真实文化、宗教与命名当前差距

2026-10-08，根只读审查者 character_integration_map / destiny_trait_index 的当前源码结果。用户选择：创建世界同时提供“按文化习惯生成新名字”和“真实历史名称”两种模式。以下为核查结果和当前批次接线点，不是已经实现或试玩通过。

## 核实的原因

- `restoration19-names.ts` 只有 EasternFantasy、WesternFantasy、Ciestundu、Leffathou、Oeczea、Wristhos 六个库。对应 JSON 的 Chinese/Japanese/English 是翻译列，不是现实文化身份。没有中华、日本、英格兰、阿拉伯等独立档案。旧库有真实与风格化条目，不能笼统声称每一条都是虚构。
- `CulturePanel.tsx` / `restoration19-culture.ts` 当前编辑五种经济族群（渔猎、农业、游牧、海洋、商业），不能修改真实文化或宗教。真实文化不能通过重命名六个显示标签完成。
- `upper14-state.ts/reconcileUpper` 使用 native-no-culture-polity 种子选择政体。`war46-session.ts` 制度编辑不联动 naming；`PeoplePanel` / `FamilyPanel` 与 `war46-politics` 登基事件固定使用“君主”。
- `war46-declaration` / `war46-vassals` 给原外交投影的 religionId 是 null；`dynasty23-validation` 要求人物 religionId 必须是 null。UI 有一个宗教标签不代表模拟已经读取信仰。
- `restoration19-names/reconcileNameEdits` 会把 world.name 变化视为玩家手动命名，清除原名 key、设为custom。自动增减“共和国／帝国”必须绕开这种误判，明确保存基础名、命名来源、自定义覆盖和派生全称。

## 下一批三个实际切片

1. **真实文化档案与双命名模式。** 新增独立文化与宗教目录，两个命名模式分别提供城市/国名/人名/姓氏资料。保持经济族群与宗教分开。新创建器在首次人物、家族、财政生成之前确定文化和政体；不能先走旧六库生成全世界再反复重抽。旧参考入口为 `settlement25-world/initialNaming`、`settlement25-create`，旧文件不改。
2. **文化+政体统一称号/国号。** 中华帝制皇帝、日本君主天皇、罗马共和国与帝国区别；共和国不沿用帝号。接制度编辑、`secede` 新国、`restoreState` 历史复国及当前国家/人物/地图显示。自动名称随改制变化，玩家自定义名与旧史书保持。复国恢复历史身份，不能当新国重抽。新史记才使用新称谓。
3. **宗教真实选择与保存。** 先接独立国家宗教选择/编辑、Worker重验、外交读取和保存恢复；个人信仰/传播尚未实现时不得声称已加入所有家族成员。若扩展人物，必须同步替换其新版本创建/继承/验证合同，不能直接给旧强制null字段赋值。

三个切片要一起接入**尚未启用的同一新规则47**；Store49是相对旧存储编号的新库，不是另开游戏规则49。文化数据与纯解析可以分别开发测试，但不得作为v46普通显示补丁冒充可玩真实文化。
