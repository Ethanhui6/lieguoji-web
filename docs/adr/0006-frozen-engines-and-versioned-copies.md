# ADR 0006：冻结规则、静态引擎目录与显式副本

日期：2026-09-23。对应 PH01。本文只描述已实现的兼容基础，行政、人物、信仰功能仍按各自 PH 开发。

## 旧世界运行方式

已发布 0.4 的确定性闭包是五个 sim/history 源文件，来自 Git `8d716dda2c92373c62f87aef700c3d93984c4472`。`src/compat/v0_4/` 保留原相对目录和 LF 规范化字节，manifest 同时保留原逻辑路径、各文件 hash 与固定引擎指纹。冻结文件不允许跟随当前规则修改。

`src/engine/registry.ts` 是编译时静态目录，不从存档 URL、文件路径或任意脚本加载规则。适配器把校验、hash、单日推进、命令执行、预览、账册、完整重算与 seek 绑定到同一引擎。创建记录时适配器自行注入完整指纹，调用方不能任意指定。

已有历史以完整指纹选择引擎，再校验历史格式及世界版本。没有指纹的普通旧存档按明确元组锁定：schema1/rules0.1.0 和 schema2/rules0.2.0 均使用冻结 0.4。新 rules 不能因为“是当前版本”获得默认兼容。

当前活动规则五文件与冻结源仍相同，因此只注册一个实际规则实现，不虚构第二个指纹。目录支持两个独立适配器的能力有隔离单测；第二个生产规则实现必须在后续真正开发后注册并增加对应存储/回放验收。界面变化、Git 提交或移动冻结目录都不改变旧引擎指纹。

构建检查当前规则清单的全部静态 import、export 和 type import，遇到未纳入指纹的依赖即失败；动态加载规则也拒绝。新规则模块必须进入完整有序清单。冻结源另验证逐文件 hash、字节数和原指纹，不能同时改 manifest 来伪造原引擎。

## 未知与损坏分别处理

已知格式1、已知旧世界结构但未知引擎的既有记录，使用冻结格式 codec 进行结构和数据完整性检查，不执行任何规则。有效 current 原样返回，不因指纹未知降级为 backup。可显示已保存事实并导出，禁止推进、预测账册、回放、分支和续写。

新导入文件必须能通过真实 Replay Worker 全量重算，才能创建带末态的归档。未知指纹文件只有日志，不一定有最终检查点；不得用初态/最后检查点冒充末态。未知文件可以读取其封装但不能被登记为已核验游戏运行。

写入层独立保护 current 和 backup：任一含未知指纹，或者候选试图在同一 slot 切换规则引擎，就拒绝。未知内外格式、rules 或经营版本仍前置锁定。普通存档 CAS 也比较 current、backup 和 revision；备份版本保护不能只由 UI 按钮承担。失败和读取均不自动修复原槽。

对于当前版本无法解析的原始数据，错误页和工坊中已登记运行的恢复路径提供「导出受保护原始备份」。仅按当前 scope 读取明确的 IndexedDB 主备/修订号键；历史记录附带只读容量来源信息，不枚举其他运行、不升级未来 DB、不创建空库。不执行世界校验和规则，不丢弃未知字段。JSON 无法无损表达或完整包超过250MiB时明确拒绝，原数据不变。`.protected.json` 是未经规则核验的救援包，当前版本不提供导入执行，不能冒充正常存档；已加入 Git 忽略和发布拒绝名单。

## 副本与升级

普通历史分支先在隔离 Worker 核验源史，再定位选定序号；Root 再读源槽、重算并比较父 hash 和源指纹。新的 run 使用源引擎创建记录，保存成功后登记到工坊。取消或失败不改源历史；工坊登记失败时保留独立新局恢复编号。

已有 schema1 到 schema2 经营副本是显式转换：`prepareManagementCopy` 只接受合法旧自建世界，冻结引擎初始化经营数据，再校验目标规则；调用方分配新 run、独立数据库，原存档不写。两个旧 rules 本来属于同一已发布引擎，不伪造不同引擎指纹。经营初始化表示副本起点的数据，不补造过去。

未来跨引擎升级必须单独注册实际转换器、预览初始化影响、先核验源时点，然后保存独立来源元数据；不能扩写严格旧 history v1 的字段，不能把升级混入普通“从此处分支”。当前不存在新版大世界转换器，因此没有假升级按钮。

## V4 版本合同

`src/engine/contracts.ts` 预留新世界 world3/rules0.3.0，地理/行政/人口/人物/家族/信仰/命令各 version1，新历史/存储 version2。它是后续实现的格式合同，不是已支持世界；旧引擎与存储明确拒绝该格式。

稳定实体 ID 区分国家、政权、行政、聚落、人物、家族和信仰。各国行政层级按 ID/顺序/职能定义，不用汉字名称推断层级。版本化命令携带世界身份、完整引擎指纹以及世界/地理/行政/社会 revision；确认前四项逐一核对。封装合法不代表领域 payload、权限或引用已合法，每个实际命令仍须独立校验并在权威 Worker 内重验。

后续 PH04 实现真实分块状态和事务，PH11/18/19/21 补各领域完整实体与约束，PH28 实现新历史；不得只靠这些类型声明宣称功能完成。
