# 非零区域锁与局部山地：实际浏览器候选

候选目标为 `tests/atlas-detail-lock-relief.spec.ts`，尚未提升、静态检查或执行。仅写本目录；没有改生产、旧测试、配置或正式计划。

单场景总时限保持 **450000 ms**。实际原生鼠标或 CDP touch 绘制一片大陆并保存；从只读存储的真实粗 quad 和细场样本选择三个 1×1 陆地区域，通过可见 UI 分别建立 bit 1、bit 2、bit 3 锁。每次预览仍核对当前持久根不变，确认后检查实际 LGAL 记录只有预期非零锁及备份链。之后一次局部山地预览和确认，要求：

- 全部粗层内容地址、细场全域 coverage 语义和锁集合保持一致，确有已存细高程字节变化。
- 三个实际 quad 的所有相交细格源节点 coverage 不变；bit 2 / bit 3 区源节点高程逐个不变；bit 1 区至少一个真实高程改变。
- bit 3 区单独解除 bit 1 后保留 bit 2；随后按真实撤销栈撤销解除、山地修改、最后一次双锁建立，核对每步根修订、备份和数据。
- 只刷新一次，最终保存修订 9、原地形、bit 1 / bit 2 两处非零锁与只读字节检查保持一致。

所有 flags 均由界面操作产生。只读观察器直接核验 manifest / block SHA-256，独立解析 LGAL、LGDC 和 LGAB；用凸多边形与轴对齐细格的 SAT（接触也纳入）收集保护节点，不调用产品的生成器或保护算法。仅取全部节点都实际存为 samples 的三个区，避免假造隐式 Hbase 高程；全域粗块不变另行保证持久 Hbase 输入不变。全域 coverage 将缺省海、uniform land 与同值 samples 规范化，表示变化不能掩盖海陆值变化。

已与 `v4-lock-ui-staging` 作者确认入口、数字选区、mask/action、预览和确认控件。保护范围与山地范围独立；测试先配置山地控制，再经保护操作返回，核对种子、起伏和默认 16×16 范围保留。复用已有 `tests/helpers/atlas-shape-readonly.ts` 的 saved/audit/metrics；未调用该文件当前不支持 v4 的 geography helper。无存储写入、flags 注入、应用状态 setter、重载重试循环或额外超时。

限制：这三个受保护区是陆地内部，bit 1 测试证明海陆保护不会错误冻结允许高程，不代表此例修改了实际岸线。实际 fixture 是否满足三个全采样区，以及各端 450 秒是否足够，尚须根统一检查并通过真实浏览器确定；当前没有任何 PASS 主张。稠密锁、性能门、取消、真机与自然视觉验收均不属此例。一次自然生成、一次局部预览、四次锁提交和三次混合撤销，未增加旧测试的执行次数。

根接线：确认目标路径仍不存在后提升单个新测试；选择该 spec 并保持 retries=0、workers=1，逐端执行。需同时提升实际锁 UI 和对应安全 snapshot 修复；原有局部山地和海岸测试保留。本候选不提供或修改 runner。
