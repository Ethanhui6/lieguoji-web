# V4 世界、行政与社会模拟合同

更新：2026-09-23。本文是待实施的世界设计与验收合同，不是功能完成或性能通过证明。遵循根目录 [CODEX_AUTOPILOT_V4.md](../CODEX_AUTOPILOT_V4.md)；唯一任务编号和状态源为 [plan/tasks.json](../plan/tasks.json) 的 PH00—PH35，续接读取 [AUTO_HANDOFF.md](AUTO_HANDOFF.md)。

最终产品是本地单机网页／PWA：自己画巨大世界，生成地理，建立采用不同制度的国家，划分行政区，创建城市、家族与信仰，让社会自主推演并能解释原因。地图创作、治理、观察、干预和历史分支共用真实规则；固定五国战役保留为预设与回归，不替代自由创世。

PH00—PH35 及子项、真机和用户视觉验收全部完成以前，只在本地开发、提交与验证；禁止新发行包、任意分支／tag 推送、远程 PR／Issue／Milestone 写入及 Pages 构建部署。现有 0.4.0 保留；最终云端 CI／预览／生产核验单独记录 `releaseVerification`，不提前算作本地 PH 完成。具体边界见 [RELEASE_POLICY_V4.md](RELEASE_POLICY_V4.md)。

## 1. 真实基线与必须解开的耦合

| 0.4.0 当前实现 | V4 需要解决的问题 |
| --- | --- |
| 世界坐标 1000×700，32×20 共 640 个 Voronoi 单元 | 放大画布不会增加真实地理精度；必须增加可编辑且参与规则的数据。 |
| 每个陆地 `DraftCell` 编译成一个 `Province`，同时承担地理、行军节点与政治归属 | 地理采样、模拟区、行政树和地图显示必须分离，不能将每个采样点都当县。 |
| 草稿最多 1000 单元；运行世界最多 50 国、1000 Province、1000 城市、500 军队 | 这是旧格式边界；改数量常量不等于完成大世界。 |
| 草稿有高程／湿度，运行世界仅留地形分类；渲染反推近似属性 | 新世界保存连续地理与水系，编辑到推演再到存档不能丢失。 |
| 国家有 `regimeId`／`dynastyId`，尚无完整人物、家族、行政制度实体 | ID、名称和空面板不能算相应系统已实现；旧 M4-004 映射 PH18—PH20，仍未完成。 |
| Worker 返回完整世界与历史，存在整局克隆、序列化与完整检查点 | 新协议须增量传输、分块保存和有界回放；先测热点，不仅把工作移入 Worker。 |
| 整图背景纹理和动态层重建 | 改为视口裁剪、分块缓存与脏区域更新；可见细节不等于全世界实体。 |

保留 TypeScript／React／Vite／PixiJS、独立 sim-core、Web Worker 与 IndexedDB。沿现有可玩循环演进，不从零重建，也不把已发布的小世界证据套用到大世界。

## 2. PH01 是规则扩展的硬前置

冻结已发布引擎的完整确定性依赖闭包，包括规则、事件生成、排序、舍入、路径、报告、历史校验和 hash；按完整规则指纹静态分派解析、校验、重算与回放，不允许存档指定任意加载路径。旧 schema1／rules0.1 与 schema2／rules0.2 均按原规则继续运行，不静默迁移。

已有 `.autopilot/compat-0.4/` 的 modern／legacy 合成 golden、预期与来源记录是 PH01 的输入材料，尚不能替代正式兼容实现。固定来源指纹为 `65333e9ed3fccd77c6e5bf32a9a3d0396df2990f2ad1ede7f952aec1217851c5`；不得借用此指纹标记新规则，不随新版实现重算旧预期。

已知旧记录须准确查看、定位、播放和导出；未知指纹只保留只读保护与导出，明确不可验证。升级必须先用旧引擎核验选定时点，再创建新 run、新初态、新指纹，记录父 run、序号、旧 hash 与指纹。取消、失败和成功分支均不改原历史及其主备数据。

旧历史 v1 的每 32 输入完整检查点、2048 输入／20 MiB 日志及全库主备 200 MiB 限制维持原语义；新格式另定预算，不通过改旧上限绕过保护。旧 golden 须覆盖浏览器 Worker 与最终离线构建，不能仅有 Node 通过。

## 3. 分层数据与稳定身份

| 层 | 权威数据与职责 |
| --- | --- |
| `GeoAtlas` 地理底图 | 世界坐标、共享顶点／边、基础地块及邻接、高程、温湿度、汇流和资源；不含行政层级假设。 |
| `DetailTiles` 地图细节 | 分块地形、岸线、水系及空间索引；装饰细节与影响规则的特征显式区分。 |
| 聚落与交通网络 | 城市／村镇／港口、道路／河运／航线、距离、通行条件和容量；一县可有多个聚落。 |
| `AdministrativeScheme`／行政树 | 各国层级定义、父子关系、叶级地块成员、治所和治理职能；上级范围由下级派生。 |
| `SimState` 社会状态 | 人口群体、个人、家族、机构、仓储账目、政权、条约、军队、法理与实控；明确各项结算粒度。 |

国家、政权、王朝、家族、行政区、聚落、文化和信仰分别拥有稳定 ID；不从名称或颜色推断身份。国都、各级治所、城市位置和地图标签分别引用。地块细化或行政拆分必须记录映射与历史沿革，不能复用旧 ID 指代另一实体。

共享边只存一个权威几何，避免相邻区各画一份边造成裂缝。基础几何、行政归属和动态控制有独立 revision；派生面积、上级人口、边界与索引可缓存，但不得形成相互矛盾的第二份权威状态。

地理底图重构在暂停的编辑分支中完成并重新校验；运行中行政改革是规则命令或明确的创世干预。普通视图切换、LOD 与低画质不能修改地理、行政或模拟结果。

## 4. PH03 锁定真实规模与性能合同

| 地理候选规模 | 定位与验收边界 |
| --- | --- |
| 16,384 | 候选基础大世界档；须测试完整实体组合，不能只有空地图。 |
| 65,536 | 标准大世界目标；须具备可编辑地理、行政、城市、人物和长期推演。 |
| 262,144 | 扩展候选档；支持设备与组合上限须实测后锁定。 |

上述数字均指地理采样或基础地块，既不是县数，也不是逐人模拟数量，更不是三端支持承诺。4,096 仅可作为诊断夹具，不能作为大世界合格交付。世界范围、地理密度、模拟区数量和可见绘制数量分别记录，不以静态噪声像素冒充模拟规模。

PH03 必须对同一固定种子与数据版本，联合测量地理、模拟区、国家／行政层数与单位、聚落、人口群体、具名人物、家族、组织、军队和历史长度；**这些组合预算在 PH03 实测前未锁定**，不得分别测上限后拼成可同时支持的承诺。

基准覆盖大陆密集边界、群岛与山地交通等场景，注明实际硬件、操作系统、浏览器、冷／热启动、测量方法和原始证据。记录启动、峰值内存、拖动缩放帧时间、编辑响应、模拟日吞吐、存读档、回放定位及长局存储增长；报告 p95 与最差场景，不能只报平均值。

桌面交互目标 60 FPS，移动基线持续可操作不低于 30 FPS；其余阈值、持续运行时长及各档组合限制在 PH03 固化。无法获取的内存指标标为未知，不用桌面浏览器模拟值代替 iOS 真机内存。目标未达时记录差距并优化，不悄悄降低标准大世界目标。

## 5. 渲染、Worker 与确定性

按视口查询可见块，分层缓存地形、边界和标签；用 LOD、标签避让、对象复用和脏块更新限制绘制量。React 管理界面，不为每个地块建立 DOM。相机平移缩放、搜索、小地图、比例尺、方向／坐标、书签、选区、图层和回到选中对象共同支持大世界定位。

Worker 负责生成、路径与权威模拟；主线程保留即时输入反馈。静态地理按加载／revision 传输，动态消息采用有界差量与必要快照；不能每 tick 克隆全世界。队列提供背压、进度、取消与过期 revision 拒绝，取消不得提交半成品。

模拟采用固定日历阶段、稳定 ID 排序、显式种子随机流与明确数值舍入；墙钟、渲染帧率、异步完成顺序不得决定结果。多 Worker 若后续需要，先确定可重演的分区合并顺序，再并行执行。相同初态、规则指纹与输入必须得到相同逐步 hash。

行政聚合、邻接、贸易路径和人物关系建立版本化索引；索引失效和重建规则可测试。低配设备降低阴影、标签密度与缓存，不能偷偷减少同一存档的人口、行政树或真实规则。

## 6. 地理生成与手工编辑

提供空白海洋、参数、种子和模板入口。海陆／海岸、高程／山系、温度／降水、水系、植被／资源按因果生成；水流沿地势汇集，河湖连通出口或明确内流盆地，地形影响气候、通行与聚落择址。不能随机换色后称为地理生成。

所有生成结果可检查、局部重算、锁定、手改、撤销／重做。海陆、高程、地形植被、河湖、城市与边界编辑必须修改真实几何和规则数据；长操作有进度与取消，一次笔划是一项原子事务。锁定海岸、国界和城市不因局部重算被默认覆盖。

草稿允许不完整；启动推演前检查拓扑、水系、实体引用、边界、治所和资源约束，并能定位问题。城市与标签分别移动。岛屿、海峡和航线不能被错误的陆地邻接穿透。

## 7. 每国行政制度、自动区划与改革

每国自有 `AdministrativeScheme`：支持省—州—县、州—郡—县、道—府—县、直辖市＋县、城邦／领地及自定义名称、层数、称谓。层级按 ID、顺序、父子关系与职能识别，名称不决定高低；可组合常规与特别行政分支，合法深度与总量由 PH03 预算约束。

制度改变真实治理规则：任命或继承、地方留税、自治范围、征募义务、治所服务半径与上级权限。中央任命、领地义务或成员自治可以成为原创模板，同一世界各国可不同，不能只改层级标签。国家制度与家族／宗族身份分离。

自动区划接收目标数或面积／人口范围、山河权重、交通半径、已有城市、边疆／沿海偏好与锁定区，执行有约束的区域生长／划分。先预览边界、名称、治所、面积、人口和冲突，再原子确认；相同输入与种子得到相同结果。

硬约束包括父级覆盖、同层不重叠、无意外空洞、邻接正确、治所合法、锁定区保留。岛屿、飞地、直辖区按显式制度处理；约束不可满足时指出原因，不偷偷删地、丢人口或造跨海陆路。

手工圈选、笔刷、拆分、合并、改隶、命名、迁治与制度改革共享预览和验证。展示税收、任命、补给、人口、道路及历史引用影响；金额、人口和库存按确定性规则守恒分配。取消不修改，确认原子提交并可恢复。

运行中改革具有成本／延迟或明确标记为沙盒干预，记录生效日与前后映射；不能重写历史行政图。行政法理、实际控制、私人地产和军队驻地是不同维度；城市失守或首都迁移不自动销毁国家。

## 8. 人口、经济与交通的共同账本

普通居民用有界聚合群体表示，按地区、文化／语言、信仰、职业／阶层建立实际存在的稀疏组合；具名人物是人口中的角色，不额外重复计人口。出生、死亡、迁徙、饥荒、征募与战损都有来源、去向和原因，非负与守恒可核对。

农业和基本资源、就业／劳力、地方产出、仓储、税收、国库、行政成本、运输、贸易及军需形成闭环。中央与地方转账不重复创造财富；资源运输有路径、时间、容量和损耗。下一日预测与已发生的实际日结分别显示。

道路、河运、港口与航线改变到达成本和运量；海运需要运输能力，不能当作免费跨海陆路。城市需求、地形产出和行政距离影响物流，贸易中断再影响粮价、军需、迁移和财政，而不是仅画一条移动线。

## 9. 人物、家族、宗族与继承

人物具备稳定身份、生卒年龄、亲属／婚姻、能力性格、职务与所属实体。家族、宗族、分支、王朝／皇室、政权和国家分别建模；家族可跨国，宗族关系可保留未知，不伪造缺失祖先。自动生成与玩家创建使用同一校验。

必须实现谱系、婚姻、分支、声望、资产／影响、地方联系、任命与执政者生命周期；婚姻、亲属、任命及继承须影响外交、合法性、忠诚、财产或职务，不能仅显示族谱。死亡、退位、罢免后世界继续运行。

继承制度包含候选资格、排序、指定／选举等适用规则、监护／摄政、争议与断嗣处理。预览候选顺序、排除原因、支持来源和可能后果；确定性解决并列。争议由合法性、实际支持与资源条件触发，不以随机掷骰强制内战。

校验亲属环、年龄关系、婚姻约束、职务唯一性及悬空继承人；生物亲属、收养／法定关系和政治任职分别表达。制度变更记录日期并只影响之后，旧继承记录和源历史不改。所有沙盒人名与制度不自动写入 CANON。

## 10. 信仰、文化与社会因果

信仰可编辑名称、符号颜色、教义、仪式历、组织、圣地、分支与关系；文化、语言、信仰、国籍和家族是不同维度。信仰组织拥有有限资源、领导代表与影响范围，教义和政策具有明确规则效果。

信仰按人口群体分布，传播受邻接、贸易、迁徙、组织投入、政策与个人行为影响，具有时间与成本；转换不创造人口，也不能无成本瞬间统一全国。仪式、圣地、组织分裂和政策改变可产生有条件的社会事件。

信仰影响合法性、地方支持与外交倾向，但同信仰不保证结盟、异信仰不自动开战。不得把某种真实信仰设为天生优劣或好战；原创沙盒的关系、政策与处境决定行为。

## 11. 外交、战争与自主推演

外交考虑利益、关系、条约义务、战争理由、停战与议和。征募、军制、指挥、路线、补给、运输、攻城、防御及战后秩序共同决定战争；保留预览确认命令、真实行军交战、撤退／占领、原因查看的完整循环。

AI 以有限信息、资源和决策间隔选择目标，给出候选、选择原因、成本与停止条件。和平约束统一覆盖寻路、战斗、追击和占领；Worker 重验命令预览状态。不能靠预定胜负、随机染色或后台增兵维持热闹。

主要因果链是地理与交通→产出、贸易与粮食→税收、军需和人口→地方权力与支持→继承、政策和条约→战争或和平→控制、秩序与生活。每个变化都有可查看的条件与贡献；和平稳定本身也是有效结果。

## 12. 大世界保存、历史与离线运行

新存储将不可变地理块、动态块、输入日志、检查点与根 manifest 分离；采用有界分段、压缩和必要检查点，不能无限保留全世界快照。可预写不可变块，但仅在完整校验、配额与版本冲突检查后原子切换根指针，失败仍可读取旧根／备份。

保持单一权威写入者、跨标签冲突检测、未来版本锁写、主备恢复与导入隔离。导入校验体积、解压后大小、实体引用及完整性；存储估算只是提示，真实配额失败须回滚。清理仅处理确认无引用的临时块，不自动删除玩家历史或真实存档腾空间。

PH28 的只读回放按原规则重算，定位后可建立独立分支；逐步 hash、父引用与源数据保护必须成立。地理／行政／人物事件在相应历史时点显示，不能将当前地图和人物状态套到过去。新日志上限与增长预算在 PH03／PH33 用实测锁定。

PH32 的安装／缓存完成后，地图、编辑、模拟、保存与回放可离线使用；首次安装需联网须明确。应用、缓存、规则、世界、历史版本分开，更新前保存并可失败恢复，不混用旧界面和新引擎。关闭页面默认停止；如设计离线快进，必须显式、有限且可重演，不声称持续后台模拟。

## 13. 完整玩法与验收归属

最小完整体验必须串起：画海陆与河山→自动生成后局部手改→建立不同制度国家→自动区划并手动拆并／迁治→建城定都→创建家族、婚姻、执政继承及信仰→观察生产、人口、贸易与稳定→处理继承和外交→预览命令并经历补给、交战／撤退或和平→查看因果→保存退出→离线恢复→回放并分支比较，原局保持不变。这是贯通验收场景，不是允许提前发布的缩水范围。

观察、治国、创世干预和挑战模式共用核心规则，权限和目标不同；自然演化与玩家干预明确标识。提供可开始、可失败、可恢复的原创内容，不能靠堆空面板宣称完整。界面合同见 [DESIGN_V4.md](DESIGN_V4.md)，每项功能都须有输入、权威状态改变、视觉反馈、原因、保存恢复和验收证据。
