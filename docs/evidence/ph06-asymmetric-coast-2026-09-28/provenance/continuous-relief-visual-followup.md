# Preview 14 连续山地：现有截图的只读视觉复核

2026-09-28。结论：曲线山脊修复了直段接头与坡度连续性，但当前真实高度场仍主要由宽的正椭圆核沿曲线叠成，峰高又沿全链作近周期起伏。因此大陆上依然出现几团椭圆土包和连接它们的细带。低地缺少与山体相关的山麓、支脊及谷地组织，是大片平原空白的主要原因。粗高程插值、较弱光照和全图缩放强化了柔软外观；现有证据不足以把问题归因于模糊滤镜或缓存降采样。

本次只读取已有图片、构建/验证记录与源码，只写本报告；未运行测试、构建、生成器或浏览器，未改生产源码或已冻结的海岸/山脊候选。这里的视觉结论不把自动流程 PASS 转为自然大陆观感 PASS，也不替代用户视觉验收或真实设备测试。

**必须先纠正的一处归因。** 两张截图都是 revision 9，在混合撤销及重载之后。`tests/atlas-detail-lock-relief.spec.ts:326` 已撤销局部山地至 revision 8；`:334` 检查恢复后的 coarse、fine、regions、coverage 与首片大陆一致；`:336` 才拍全图。它们展示的是种子 `fine-local-relief-native`、size 256 的首片大陆，即 world 模式的自然山地。局部山地曾使用的 3600 米、16×16 范围以及新的旧地形背景插值已经撤销，不能用它们解释这两张图。也不能把“局部宽度已经随选区收缩”当作这里宽土包已被解决的证据。

**图上能直接看到什么。** 两图均有两条明显山带：一条较短较浅，另一条由数个较大的椭圆灰褐色高点组成，峰间连接细而软。高点形状及色带相似，读起来像一串土包。大陆大片外缘和北部是变化很弱的橄榄色平地，山体到这些平地的过渡缺少能辨认的山麓、支脊及谷地。平板较大的地图显示面积没有消除这一结构。海岸形状问题另有冻结候选，本报告不重复诊断它，也不把海岸改动当作山地结构改进。

图片查看工具对原图进行了适配缩小，因此这里不做原生像素模糊宽度、纹理频率或手机/平板清晰度排名。平板山面隐约可见的细纹仅记为待原像素验证的现象，不能据此认定存在某个 shader 接缝。UI 比地图锐利的观感也不直接证明地图用了 blur。

**真实高度场的首要原因。**

| 源码事实 | 对当前画面的解释及限制 |
| --- | --- |
| `detail-curved-ridge.ts:57` 的核为 `peak × (1 - radius²)³ × weight`，`radius² = along² + (across / width)²`，沿向支持长度取宽度的 0.35 倍；节点在真实曲线上积分，全部为正。 | 共享切线保证曲线连续，不会自行产生山系的支脊、分水岭和谷地。宽椭圆核仍倾向给出圆润横断面。土包不是旧直线接头三角残影，但自然性也未随 C1 连续自动成立。 |
| `detail-curved-ridge.ts:88` 使用 `max(128 world, 链长 / 3.7)` 波长及轻微相位调制；峰高包络是 `.25 + .75 × wave²`，以链内最大锚点峰高作为统一幅度。 | 足够长的链大致保留 3.7 个宽峰周期；鞍部显著降低、高峰形态重复，叠加宽核很容易读成球串。相位不等距和连续曲率都不足以消除这类重复山体。这里没有实测每座峰间距，不把公式周期当作图片计数。 |
| `detail-natural-relief.ts:70` 先选整体长轴；world 模式在可用短跨度足够时规划三个独立链组，主链 9 个锚点，其余各 5 个，位置是沿同一长轴加侧偏和弯曲。 | 源码请求最多三条独立山带，不是相连的主脊与逐级支脊网络。实际图上两条明显山带与之相容；不得把请求组数当作实际可见组数。 land probe 与拒绝海上跨度仍有必要。 |
| `detail-natural-relief.ts:91` world 主链基础宽度为 88–200 world，次链 60–172 world，且最低为四个 coarse step；size 256 的 step 为 16 world。 | 这里宽度接近横向支持半径，主链总支持尺度约 176–400 world，再有 ±15% 侧宽变化。对这片大陆是很宽的起伏，不能靠更密的画面像素把它变成细分山岭。 |

**采样与显示是第二层原因。** `detail-shape-natural.ts:284` 先将自然高度写进实际 coarse 重心；`:287` 用这些持久高程建立 Hbase。`detail-shape-height.ts:16` 的 compact IDW 支持半径为 2.5 个 step，本例为 40 world，真实重心处精确复现，中间作平滑加权。沿海 sampled tile 才在 `detail-shape-natural.ts:294` 将 nearHeight 与 Hbase 按海岸距离混合；uniform 陆地仍依赖 Hbase。2 world 的真实细海岸网格，不等于整个内陆已有独立的 2 world 地质细节。

这条重建链会进一步弱化接近 16–40 world 的小变化，却不能独自制造几百 world 宽的椭圆峰簇。不能为了显得细致而悄悄改旧世界的 Hbase 解释；若后续确实需要更小的内陆地貌，应通过明确的新生成候选和可保存的实际细高程获得，仍需保持存档、锁、撤销与重载的一致性。

`detail-terrain-shader.ts:8` 的光照因子为 `1 + atan((gx + gy) / 40) / (π / 2) × .13`，限制约 ±13%。它将一个方向的坡度压成较弱亮度变化；例如公式输入 `gx + gy = 10` 时仅约 2% 变化，这是公式示例而非截图实测。`terrain-material.ts:4` 按绝对海拔连续插值颜色，低地 0、300、650 米是相近橄榄/绿，1200、2400、4200 米转向深绿、灰褐、浅灰。于是宽峰的闭合高度区间在图上变成椭圆色块，缺少真实谷地时更像柔软的彩色土包。

当前 shader 标识是 `final-q8-pieces-gl2-shared-light-v2`，读取实际 signed16 高度页后沿真实片元几何着色，并使用共享节点的同域坡度。此次没有看到地形 Gaussian blur 调用的证据；不能把已修的共享光照连续性问题重新当作默认解释。颜色 LUT 的线性取样也不是对真实高度页做模糊。

全图缩放本身也有限制：按屏幕显示的约 9% / 18% 估计，2 world 细步长仅占约 0.18 / 0.36 CSS 像素，16 world coarse 步长约 1.44 / 2.88 CSS 像素。`renderer.ts:113` 的 DPR 上限为 2；`render-density.ts:30` 依据相机 scale 和 resolution 决定纹理密度，超过预算才退一级。没有这两张图对应的实际 `fallbackReason` / `density` / `outputPixelsPerTexel` 证据，不能断言发生了缓存降级；提高 DPR 或纹理密度也不能生成不存在的山谷。

**下一步最小可验证修改建议。** 保持海岸候选独立、同一 coast / seed / 大陆范围，不同时换 shader 或配色。先做一个真实地貌结构候选，再做一批配对验收；不扩成完整侵蚀系统，不用高频噪声掩盖结构。

1. 在现有有界曲线索引和真实 land probe 基础上，先做一条主脊与少量相连的短支脊；支脊从主脊向外递减，主脊之间保留真实低谷。峰鞍改为少量不等长度、不等幅度的事件；横断面同时区分较窄的脊顶、较宽低幅山麓和侧谷。仅打乱现有 cos 峰间距仍会是一串不等距球，因此峰位与横断面必须一起调整。主脊/支脊交汇不能因正核相加重新变成更大的圆包；此项应通过实际高度的交汇截面验证。初批尺度保持能被现有 size 256 采样可靠承载，避免把未解析的小细节交给插值“补出来”。
2. 对相同输入保存原候选与新候选的真实高程证据：从持久 coarse + Hbase / 实际 fine 数据输出灰度高程、固定间隔等高线及主脊/支脊/谷地横断面，并保留重载后的字节/采样一致性。建议同一片区域同时检查全图、25% 和 100% 视图；阈值从地形采样尺度和指定地貌幅度定，不以临时调到好看为依据。至少验到：主脊与支脊确有高程连接；支脊向外下降；谷地是真实低值且在保存/重载后仍在；低地到山麓有连续宽度层次；不再主要由相似的闭合椭圆等高圈解释整条山系。闭合峰顶等高线本来正常，不能把“任何闭合圈”设为失败。自然观感仍由实际配对图与用户确认。
3. 结构成立后再单独判断显示：以完全相同的已保存高度字节做正常材质与诊断灰度/光照对照，记录相机、DPR、raster density、fallbackReason 和 outputPixelsPerTexel。若灰度/等高线已有支谷而正常视图看不到，才小范围改坡度光照或尺度适配；保留高度 nearest 读取、CPU/GPU 解释一致及共享节点连续性。不是仅换色，也不通过展示不存在的装饰山线、河线来通过验收。

下一批必要回归仍是有界查询、确定性、取消不写、真实海陆保护与通道、锁与撤销、保存重载、同一高度解释。上述只是下一批建议与量测方案，尚未实施或执行。国家、城市、兵种及行政区继续按原 PH 实现真实数据和规则，不作为地貌不足的视觉填充。
