## 2. 重做的理由与保留项

已有 preview.33 是可以生成、保存和编辑数据的工程基线，但用户未认可画图体验。关键问题有：手绘轮廓与提取的高度生成器未接通；已有陆块相接/重叠常被安全提交限制；有限源地形经过转换后放大不会自行产生细节；每次候选预览绑定全量准备，影响快速塑形。代码锚点见 [现有引擎审查](evidence/fms-web-replan-2026-10-04/EXISTING_ENGINE_AUDIT.md)。

保留旧引擎、历史、存档、测试和来源记录。相机锚点、取消、版本保护、事务保存、Worker 可复用。新样机建立独立创世会话与存储空间，允许局部替换地理/渲染通道；不得为了接旧 Atlas 而牺牲第一份体验，也不得假定全盘重写更好。

先问清产品选择并观察原作，再做小切片；先让用户能画出满意的大陆，再做完整世界。后续功能要挂在同一地图、同一实体与同一模拟状态上，不能用另一套旧640单元演示冒充大世界完成。

## 4. 先做细的前三阶段

### WEB-PH00：基线与有界恢复（每批1—3项）

- **WEB-00-02 参照操作表**：寻找并实际观察原作公开演示；记录来源、发布日期、观察时间点、是否同安装版本。至少覆盖画陆/擦海、半径强度、取消撤销、生成时机、缩放和工具布局；尚未看清的标未知，不靠标题补齐。目前已取得视觉片段，完整画笔流程仍待补足。
- **WEB-00-03 单次画笔数值合同**：限定 `DrawMapHeightLogic`、`DrawMapHeight`、`GetCellIndexInRadius`，记录参数、选择点、改前改后高度、刷新入口及不确定项。静态确认后再构造最小本地 fixture；没有原作运行对照时不称等价。

### WEB-PH01：能反复修改的海陆画布

- **WEB-01-01 独立入口与触控**：原作风格地图占主画面，竖屏折叠工具；清楚区分浏览/绘图工具。单指当前工具，双指平移缩放；双指介入和系统中断结束未确认笔划，不能落下误触；按钮触区拟定至少44 CSS像素，真机验证。使用独立试验世界和命名空间。
- **WEB-01-02 轮廓与海陆笔刷**：闭合轮廓、陆地添加、海洋擦除、半径/强度、连接大陆、挖海湾和分离岛屿。操作作用于真实海陆/高度数据；闭合失败给就地反馈，不要求用户知道拓扑术语。自交输入的修复/提示策略经样例确定，不静默改变大轮廓。
- **WEB-01-03 编辑持久化**：每笔事务撤销/重做，局部预览与正式保存分离；候选可取消，保存后刷新恢复；独立库版本锁、冲突提示；旧档逐字不变。草稿不必有完整国家即可保存。

### WEB-PH02：第一份判断方向的试玩

- **WEB-02-01 轮廓约束自然化**：宽海湾、狭颈、长海岬、小岛组成固定不对称样本；主体轮廓锁定，细化带显式可调。试验复用高度核如何受轮廓约束；不是先随机大陆再硬裁一下就宣布完成。山脉/盆地/水系产生相互关联数据；锁定区域不能被重掷。
  - 2026-10-04海岸合同补充：默认生成仅改变内陆，固定原始跨海陆三角形和海平面顶点的高程，实际线性h=20轮廓位移上限0世界单位；阴影/水系不要求颜色不变。mask相等不能代替轮廓度量。显式海岸细化须另定有单位上限及保护样本，任意玩家锁区仍待实现；本条不减少原验收。证据见[海岸保形合同](evidence/fms-coast-preservation-2026-10-04/COAST_CONTRACT.md)。
- **WEB-02-02 海岸、海洋与缩放**：直接源地形展示 vs Atlas转换展示使用同一种子/相机作对照；分辨源算法、重采样与材质问题。海洋深浅/岸边过渡、海岸边线、陆地阴影与图层配色对照已观察材料；不得用随机噪点和规则波纹替代自然细节。全景、4/16/40倍是固定观察点，并检查其中连续过程；倍率不是画质证明。
- **WEB-02-03 手机样机验收**：真实 iPhone13ProMax 的 Safari/Chrome 各完成下面流程；桌面、移动仿真分别记；生成耗时、输入反馈、帧时间、内存/进程稳定性、保存恢复单独报告；没有工具可测的数字标不可得，不估算成通过。用户评判“方向对不对”保持独立结果。

第一份体验门的实际操作：打开空白海洋 → 画带宽海湾和细岬角的大陆 → 笔刷连接一块新陆地 → 海笔刷挖海湾 → 撤销再重做 → 自动自然化 → 连续缩放检查海岸/内陆/海面 → 再修改一处 → 保存 → 刷新 → 继续同一张图。

第一份样机采用原作风格但仅放有功能的工具；国家、战争等入口在此时不摆空壳。绘图结果可以局部、暂时不适于模拟，但必须诚实可保存，不能每次都清空重新生成。

## 5. 技术试验与判定

安装包是 Windows PE/IL2CPP，不是图片中 ELF/DWARF 的对象。沿用其“索引—小函数恢复—编译—行为对照”的方法，适配现有 Il2CppDumper/Capstone/UnityPy。当前没有已确认可用 hk4e-mcp。候选 Cpp2IL/AssetRipper 只有在当前工具具体不足时再作有界试验，恢复失败如实报告，不直接升级为全项目逆向任务。

Unity 安装产物不等于 Unity 源工程；恢复资源、类名、DummyDLL 也不等于可直接打 WebGL。Unity2021.3 的官方文档对移动 WebGL 有明确支持限制，因此不能把“重建Unity→导出WebGL”当作已经验证的 iPhone 路线。现有网页框架先承载小切片，数值算法与表现层分开验证。[IL2CPP](https://docs.unity3d.com/2021.3/Documentation/Manual/IL2CPP.html)、[WebGL构建](https://docs.unity3d.com/2021.3/Documentation/Manual/webgl-building.html)、[该版本浏览器支持](https://docs.unity3d.com/2021.3/Documentation/Manual/webgl-browsercompatibility.html)。

固定两种地理展示的同一输入、种子、坐标与海平面；记录轮廓偏移、狭颈/主要海湾连通性、陆地面积、选点高度、生成/转换耗时及截图视角。保护轮廓带和自然化幅度的数值阈值属于试验参数，必须由首批样本与用户效果选定，不能倒改阈值迎合已经生成的结果。

最初性能目标（待具名设备实测）：触控反馈p95在100ms内，导航争取60FPS/持续至少30FPS；长生成异步有进度可取消，缩放时不执行全世界重新生成。不把桌面测量冒充手机结果，不能为了帧率静默改变同一世界的地理或模拟规则。世界可支持规模由样机实测确定，旧65k/262k等目标保留为规模要求，不是目前能力承诺。

以下任一情况表示第一体验门不通过：主体大陆被换掉；无明确同意切断狭颈或填平主要海湾；细化主要呈规则锯齿/波纹；可见方格或瓦片接缝；缩放海岸/材质跳变；显示与拾取/保存不同；菜单挡住大部分地图；触控误画；修改了旧档；仅测试绿灯而用户仍不认可。失败后修同一切片，不靠增添系统掩盖。
