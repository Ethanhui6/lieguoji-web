# 开局按主要陆地连片取景；默认大陆真实面积仍只有约 1.92%

## 发现与改动

原开局相机把任何 h≥20 的地形点都放进同一个 bbox；远处微小岛屿会拉远主体大陆。现在复用与政区一致的 h20 真实裁剪三角面，按共享边连通成陆块，以真实面积筛选：始终包含最大陆块，其他面积占总陆地至少 5% 的陆块也纳入。这个 5% 是仅用于初次取景的网页启发式，尚无证据称其为原作规则。多大陆可以同屏，零散小岛不会从数据、地图、模拟或存档中消失，“显示全图”仍展示完整海图；旧局保存过的镜头继续按原保存镜头恢复。

固定默认“生成大陆”地图的渲染器 `data-land-area` 为 **45,278.84355 平方世界单位**，世界范围 **1536×1536**，陆地面积占比约 **1.9192%**。这不是摄影错觉：当前自动样本实际只创建了很少陆地。原作用户截图没有同一种子和相机参数，无法从这一比例直接证明原作目标值，但全图前后图都显示当前陆地显著偏小。

## 同样地形的浏览器观察

本地预览同一默认地形流程，旧镜头与新镜头均留桌面、手机尺寸初始图及“显示全图”图。地形面积读数一致，世界建国时名称和城市具体位置可变化，因此城市横向跨度只是画面观察，不是严格同状态逐像素差分：桌面初始城市跨度约 **557 → 989 CSS px**；手机尺寸约 **285 → 283 CSS px**，没有改善。全图跨度仍约桌面 **189**、手机 **81 CSS px**，吻合地形比例低而不是全图按钮失效。新桌面图可见主体大陆更大；手机纵向空海和孤岛首都图标仍明显，须另做真实地图布局／城址容量改进。

浏览器流程还执行了真实地图城市点选、详情、收起、全图切换；联跑的海面流程覆盖编辑器→进入文化世界→保存→刷新继续，桌面与手机尺寸 Chromium 各 2 条，共 **4/4**，页面异常 0。手机为 Chromium 视口仿真，**不是** iPhone 13 Pro Max Safari／Chrome 真机。
