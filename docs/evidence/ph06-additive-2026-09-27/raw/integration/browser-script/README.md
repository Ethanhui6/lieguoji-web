## 单一场景

1. 读取正在服务的 `/build.json`。必须实际包含 `addDetailGenerator.sha256` 和首片配方 SHA；当前不含追加配方的 preview.7 会在创建世界前明确失败，不能借用旧构建证明追加功能。
2. 通过表单新建 256 规格 v4 世界。通过正常创世面板设置种子并关闭岛链，本场景聚焦追加事务；不代表自然视觉或所有生成参数验收。
3. 用原生鼠标或 CDP touch 画左侧大陆，预览确认保存。只读校验真实 LGDC owner、SHA、海陆符号与节点高程，并选择同一个粗地块内的两个同号细格作为海陆探针。读取完整粗高程层，记录第一片及其 Hbase 支撑区域内的高程摘要。
4. 用实际导航、定位、放大和拖动将探针移到画布可点击位置；分别点击实际海陆，验证页面分类及高程落在独立存储节点的真实范围内。
5. 原生画右侧分离大陆。预览时比较数据库总摘要和主档字节，确认没有提前保存；截图预览后确认。新增记录须绑定实际运行构建的追加配方 SHA；第一片所有 owner SHA、几何引用和旧区域高程摘要须不变。
6. 在同一个会话、刷新之前点击撤销，修订应递增为 3，实际地理与首片完全一致，backup 保留撤销前的第二片。
7. 再原生画第二片并确认，修订为 4；地形须与首次追加结果一致。刷新后核对主档、细场、实际渲染摘要和第一片海陆探针，截图恢复后的两片大陆。
8. 再画与第一片重叠的轮廓，要求有具体中文拒绝原因、无候选、当前显示仍为已提交内容。主档字节和整个数据库摘要必须不变，覆盖 current/backup/manifests/content stores。

一共四次生成尝试：第一片、第二片、撤销后第二片、最终重叠拒绝。没有额外的取消重生成、GPU丢失恢复或全参数巡回；这些已有其他用例。本测试的 450 秒是四个正确性步骤的整体上限，不作为性能指标，不设自动重试或机器耗时通过门。

## 定位与独立证据

- 复用 `data-testid=atlas-studio/atlas-canvas/atlas-picked-surface`、实际 aria label、命名 region 和 navigation；不使用 CSS 的排列位置或文案全文推测操作状态。
- 用现有只读 renderer metrics 把世界坐标映射为屏幕坐标。绘制和拖动每个输入点都检查 `elementFromPoint` 命中真实画布，遮挡会失败，不通过强制点击绕过。
- 桌面使用 `page.mouse`；mobile/tablet 使用实际 CDP `Input.dispatchTouchEvent` 与 `page.touchscreen.tap`。不注入地图、相机、选中状态、存档或配方；没有应用模块运行时导入。
- 等待实际 generation preview、ready 状态和 GPU 完成帧，不靠固定 sleep。近景放大遵守产品现有 fit×80 上限；手机上不会强制要求桌面 scale 8。
- LGDC 观察器根据西/北 owner 规则独立读样本，只用四角都来自持久 samples 且严格同号的细格；避免把粗格中心、插值猜测或隐含 Hbase 当成海岸真值。
- 所有首片 owner SHA 不变证明该片覆盖/高程源字节保留；第一片左区粗高程与全部几何引用不变，覆盖旧隐含高程的实际支撑输入。这里只保证本场景第一片，不声称全世界任意区域的视觉正确性。
- 页面高程只显示整米，故用同号细格四角高程的闭包范围核对；精确字节保护由独立存储摘要承担，不把屏幕坐标误差包装成精确同点值。
- 输出 `additive-persistence-observation.json`，携带真正服务的 build 身份、实际根/备份、原owner引用、海陆探针、拒绝前后摘要；还输出预览和刷新后两张截图。输出是执行时生成，本暂存目录没有预填 PASS 或恢复 provenance。
