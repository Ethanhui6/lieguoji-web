### 七 页面和完整操作流程

审查原作实际存在的页面和流程，再建立网页对应入口。至少让以下玩家任务有完整闭环：

1. 进入游戏，识别继续游戏、新建世界、地图编辑、设置和存档入口。
2. 在空白海洋画世界，或按已核实模板、种子生成，预览后确认或取消。
3. 修改地形和外观，撤销、重做，保存草稿，刷新后继续。
4. 在同一地图建立国家、辖区、城市和首都，完成必要校验后启动时间。
5. 暂停、继续、单步和调速；观察国家与军队，查看事件原因。
6. 选择国家、城市、人物或军队，打开对应信息，定位并返回地图。
7. 预览并确认外交或军令，观看状态和地图结果，再保存恢复。
8. 阅读史书、查找旧事件、定位对应地点，回到当前世界。
9. 导出备份、导入副本、继续旧局或按规则创建新局。

没有实现的入口不要包装成可以玩的功能。空状态说明如何开始，失败状态保留用户输入并提供下一步。关闭面板、点击地图外部、返回键、Escape 和触控手势的含义统一；输入文字时快捷键不触发游戏命令。

### 八 海陆地形与自由创世

保留并完善闭合轮廓、陆地笔刷、海洋笔刷、半径/强度、原 Hill 或已核实高度工具、模板生成、局部塑形、保护区域和连续编辑。

一条连续笔划是一项可撤销操作。能连接两块陆地、挖宽海湾、切断海峡、形成岛屿和修正边缘。自交或无效轮廓需就地提示或采用明确修复策略，不静默替玩家重画整个大陆。

自然化必须保持我的主体形状。默认内陆自然化遵守现有海岸合同：原始跨海陆三角形与海平面顶点的高程受到保护，真实 h=20 等值线按合同保持。显式海岸细化单独展示范围、强度与有单位的偏移上限；狭颈、主要海湾、岛屿连通和玩家锁区均要验证。

最初主体轮廓、当前编辑结果、候选结果和保护区域的关系必须清楚。允许我主动改变海岸，但不能在每次自然化后把漂移后的形状当成从未改变的原始轮廓。生成候选支持取消、原图对照、确认，取消后恢复真正原图和对应派生数据。

高程、山脉、盆地、河流、湖泊、温度、降水和地貌应从实际数据产生。地图显示、鼠标/触摸拾取、地图编辑、存档与模拟读取同一地理事实。图层不能用装饰线条虚构不存在的河流，缩放不能切换成另一份地形。

河流逐项核对分水岭、源流、汇流、河口、线宽、曲折、湖泊和海岸裁剪。地貌使用的河流与画出来的河流应相符；实际流量单位和网页适配限制按来源说明，不能将任意累加量标成物理流量。

地理采样、显示网格、模拟辖区和行政层级分开建模。细化显示不等于增加模拟人口；国家区划不能改变海陆形状。后续缩放优化也不能悄悄合并国家、删除城市或消除海峡。

### 九 国家辖区城市与首都

国家、政权、行政单位、城市、人物和军队分别有稳定 ID。国名、颜色、制度与边界是可维护数据，不是画布上临时贴的字。

保留手工和自动建国，支持在现有世界中命名、配色、分配或调整有效陆地。自动分布国家不得重新生成已确认地形。操作影响现有城市、道路、军队或历史时，明确预览变更范围。

延续当前细辖区与一块一城的用户要求：每个有效陆地辖区有一座实际城市，城市位于本辖区内部；默认普通新城不凭空成为堡垒。细分后土地面积与归属覆盖一致，不能漏地、叠地或制造跨海陆邻接。当前默认细分参数是网页实现，不自动称为原作算法。

同国允许多片不连通领土。按实控连通块分别显示国名，法理归属和实际控制分别存储、展示与计算。

首都必须引用有效本国城市。首都失守后按当前用户要求取消该城的有效首都标记，保留其城市与历史；国家还有领土时不能直接宣告亡国。国家失去全部实际控制领土后的覆亡规则、残余军队和城市历史分别处理。迁都、重新夺回和复国之后按当前实际状态重算标记，不能遗留旧图标。

完整行政体验包括各国不同制度、不同层级数量和称呼，自动划分后可手动修改，以及跨层级的一致引用。当前细辖区是基础，并不等于这部分已经完成。具体制度和称谓优先依据原作与我已确认的需求，不擅自编成复杂的新政治游戏。

### 十 自主发展经济与看海

从我的地图进入真正的模拟，原始编辑草稿和运行世界保持独立。无手动命令时，各国仍能依当前规则作出决策。暂停后状态停止，单步推进规定的时间，倍率改变推进速度且保留规则语义。

人口、粮食、征募、军队消耗、城市与地区发展等已存在规则要实际运行。财政、税收、贸易、科技等若在原作或既定完整需求中存在，纳入对照与实现；未核实前不凭空填一排无效数值。

每项资源具备来源、消耗、转移、上限、短缺与恢复的明确规则。国家面板汇总真实辖区数据；实际完成的日结与下一日预测分开显示。战损、动员、复员、占领和运输影响相应人口、兵力与库存，避免重复计算。

自主行为应有原因：为什么选择发展、防守、征兵、宣战、进攻或议和；目标为何可达，资源是否足够，既有玩家军令是否受到影响。允许合理的长期和平，不用定时随机宣战制造热闹。

记录同一个测试世界持续推演的结果，覆盖安稳发展、相邻竞争、实力悬殊、粮食不足、孤岛与多个战场。每个场景说明实际发生什么及其原因；不提前写好战争胜者再播放动画。

长时间看海时，地图平移、缩放、信息查看、定位与暂停应持续响应。模拟过载需要清楚反馈，不在后台丢弃整段时间或把所有国家冻结后仍显示在运行。

### 十一 外交战争陆军与占领

外交行为先核实原作类型，再逐项实现其条件、数值影响和后续约束。已有宣战、停战、和平保护等继续接入实际寻路、接敌、战斗、追击和占领。联盟、附庸、吞并、谈判等待核实/未完成内容单列，不用同一按钮改个名字就算实现。

重要命令支持选择目标、预览、确认和取消。Worker 在确认时重验当前 world/run、日期、事件游标和必要版本标记；局势变化后拒绝过期命令。确认前不扣资源、不调兵、不改外交；重复确认不重复执行。

陆军应包含已证实规则下的编制、兵种、兵员、征募、补给、行军、接敌、战斗、撤退、击溃、返乡重编、补员和占领。UI 与地图使用同一部队状态。

- 行军经过有效道路或地理路径，不穿海，不越过当前规则禁止的国境，不因为隐藏面板而停止。
- 道路中相遇的敌军可以按真实规则交锋，双方人数、伤亡与行动阶段变化有证据。
- 包围、攻城、守军、空城接管、地区抵抗等按已经存在及后续核实的规则执行，避免同一地区被重复占领结算。
- 常备征募、紧急动员和人工布兵影响真实兵源和资源，不能无代价复制军队。
- 击溃返乡、重编、恢复行动与连续补员区分显示；回乡目的地失守、亡国、路线断裂等要有处理。
- 战争统计区分战斗伤亡、饥饿、动员、复员、溃散等来源，避免统计和当前人数互相矛盾。
- 结果说明参战者、地点、时间、损失、控制变化及关键原因。需要长文本时打开详情，不淹没地图。

远景看势力和战线，中景看军队与路线，近景看同一部队的真实兵种和动作。士兵数量可以用有说明的表现比例，但不能显示与数据无关的装饰兵种、虚构战斗或提前判定的战果。

### 十二 海军跨海运输与海战

在现有手动运输与持续海战基础上核对原作海军流程，逐项补足港口、舰队、航路、载军、补给、接敌、损伤、撤退、登陆与恢复。

航路必须在真实可通航水域内，陆地、海峡和岛屿影响路径。海岸附近的陆军不能直接瞬移到另一块大陆。

载军时军队拥有唯一身份和明确状态；登船后不同时在陆地继续战斗，登陆后不残留在船上。运输能力、目的港、载军限制、舰队沉没或撤退、港口易主与保存恢复都要核对。外交变化必须同时约束陆地和海上行为。

海战持续推进，伤亡、舰队状态和运输中的陆军处理遵循真实规则。舰队动画、航线、面板和历史一致，不能用移动船图标替代海战。

自动跨海远征、封锁、护航等目前未完成或未核实项，先列清原作依据和依赖，再按完整移植目标推进。手动运输成功不能替它们验收。也不要因未来海军大系统未完，停止交付已可玩的陆战与运输闭环。

### 十三 人物君主家族制度与信仰

人物必须是有 ID 和状态的实体。君主、官员、将领、家族和信仰的功能以原作实际范围与我已确认的完整需求为准，并要被模拟消费。

当前已经确认：君主同时显示“王号几世”和“本国第几任”。两套计数分别保存。例如以下仅为计数示例：某国先后使用“永宁”“景和”“永宁”，第三位可以是“永宁二世、本国第三任”；另一国的“永宁”另行计数。恢复旧王号续号，复国按本国身份与历史规则衔接；不能把国家总任次直接当作世数。

传位要真实更换任职者、记录前后人物和时间；能编辑的继任王号在确认前预览。无旧史证据时不要伪造先王列表。姓名来源、姓与名的顺序、同名辨识和文化命名规则均应可追溯。

完整家族树需要真实亲属关系和身份，继承需要可解释的候选资格、顺序及例外。寿命、生死、婚姻、生育、亲属继承等先核实原作，不能用随机换名字冒充家族系统。

叛乱、独立、内战、复国、政体变化、附庸关系等必须改变实际国家、辖区、城市、人物、外交、经济和军队状态，并形成事件。当前有限的传位、地方起义、和平独立不等于已经复刻原作全部政治公式。

信仰与文化如果影响归属、人口、冲突或政策，就要在相关规则和原因中体现；名称、色块和面板本身不能算系统完成。原作没有但我已明确要求的扩展保留独立标识，避免将扩展误写成原作行为。

### 十四 顶部要闻史书与历史查看

顶部要闻用于及时告诉我发生了什么，独立史书用于长期追溯。两者从同一个真实事件来源读取；临时操作提示另行处理。

顶部消息应有事件优先级、清楚的国家/人物/地点名称、可查看原因和定位的入口。普通与重大事件的展示时长、排队和动画根据最新原作证据及网页适配记录实现。重要事件来不及展示也必须进入史书。

史书至少能表达日期、事件类型、当时国家与人物名称、地点、前因和结果、涉及的稳定实体 ID。支持按当前范围筛选、检索或定位；后来改名、改国色和领土变化不修改既有历史快照。

建国、宣战、重要战斗、首都失守、迁都、传位、起义、独立、覆亡、复国等只有在实际发生时写入。同一事件不重复，多次事件不丢失。临时日志条数上限不能截掉永久历史和君主任次。

历史回放与历史分支是单独的完整功能：如果提供，就必须恢复那个时间点的真实状态；从历史另开一局生成独立 run，不改写原时间线。仅有事件列表不能称作已实现回放。

### 十五 存档导入导出离线与更新

草稿、运行世界、备份、测试战役和历史版本按现有设计隔离。保存包含继续推演所需的地图、实体、时间、命令、随机数状态、外交、资源、历史与规则版本，不能只保存截图或种子。

保存写入应具备现有的事务、版本验证、revision/CAS、多标签冲突拒绝和备份保护。存档损坏、未来版本、容量不足或中断时保留已有有效数据，并显示可采取的恢复方式。

旧局继续使用其原规则；明确复制后才进入新规则的独立存储。旧局主档和备份不写。更细辖区如果会改变地理结构，必须与“保留原地形重新开局”区分，不能把旧军队的 home、路线和人口悄悄映射成另一张图。

导入先校验格式、大小、版本与引用，再预览目标；默认导入为独立副本，覆盖行为需要明确确认。导出文件附有足够的版本信息。生成测试样本，不用我的个人存档作为方便的测试素材。

PWA 要验证首次安装、离线打开、资源缓存、旧版本继续运行、新版本提示、更新失败和恢复。更新过程中不能强制刷新而丢掉未保存修改。跨设备和跨浏览器优先使用明确的导出导入，不把同一设备上的两个浏览器假称共享 IndexedDB；云同步按真实授权和产品范围另行实现。

### 十六 桌面手机平板与输入细节

目标设备优先 iPhone 13 Pro Max，Safari 与 Chrome，竖屏优先。用户已报告 iOS 27，具体构建号实际测试时记录，不根据桌面仿真猜测。桌面和平板也必须完整可用。

桌面保持原作工作流与已核实快捷键。核心功能同时有可见入口，避免只能靠右键、hover 或组合键才能操作。滚轮缩放以正确的地图锚点为中心；调整笔刷时不意外缩放页面。

手机当前工具决定单指绘图还是浏览，双指用于平移缩放。第二根手指介入、手势取消、系统打断时结束或取消未确认笔划，不能留下误画。使用指针捕获及正确的取消处理，触点移出画布后仍可靠收尾。

工具菜单折叠；选中对象、当前时间、暂停和返回仍容易找到。抽屉打开时不错误穿透点击到底图；菜单内部滚动不拖动世界。输入法弹出、屏幕旋转、浏览器地址栏伸缩和安全区域变化都不能把确认按钮挤到屏幕外。

重要触控目标争取至少 44 CSS 像素，允许图标本身更小。小尺寸下保留地图可见区域；不得仅把桌面整个界面按比例缩小。长国名、长人名、满屏事件、英文数字混排和最大字号设置要有实际检查。

记录真实设备的运行结果。428×926 的 Chromium 仿真能证明布局，不能证明 iPhone 上的触控、WebKit、GPU、内存或 PWA 已通过。缺少真机条件时继续完成可做的工程，明确保留那一项待验收。

### 十七 动画音效设置与辅助体验

原作已有的动画、音效、音乐和设置需要逐项清点。复用经过授权和来源检查的资源；只提取当前用到的部分，保留实际许可与来源。原作是否有某种声音尚未核实时先标未知，不自行增配后声称忠实复刻。

战斗、行军、海战、选择、按钮和事件反馈应由实际状态触发；暂停、调速、减少动态偏好和页面后台状态都能正确处理。画面上的余留动画不能在逻辑结束后继续伪装交战。

声音按浏览器允许的用户交互启动，提供音量、静音与当前支持的分类设置。切换页面、暂停、后台恢复和更新不能叠加重复音轨。声音开关确实生效并按用户选择保存。

设置范围对照原作，包括地图图层、标签、海洋网格、显示质量、速度、声音与操作提示等实际存在的项目。质量设置可以调整渲染成本，不能删除真实国家或改变战争结算。

焦点、键盘操作、可见选中、足够的文字对比和减少动态要可用。颜色之外用边线、图例、图标或文字区分重要状态，同时保持原作风格。

### 十八 性能与工程边界

渲染、模拟、地图编辑和存储职责清楚。高成本地形、气候、河网、区划或推演任务采用现有 Worker 架构；取消、过期请求和失败回退必须与实际目标世界一致。迟到的结果不能覆盖新地图或用户刚切换的显示。

Worker 消息带必要身份与版本信息；频繁切换候选、撤销重做、复制旧局、开始新局、暂停和加载时验证竞态。加载状态只能表示真实工作，不能用假进度掩盖失败。

优先使用不可变共享几何、适当空间索引、视口裁剪、标签分级、合理缓存与分帧/后台任务。调优前后核对同一输入的完整规则输出；不能通过删军、减城、降低原断言或省略日结让性能“达标”。

每个性能结论写明设备、浏览器、地图规模、国家/城市/军队数量、倍率、测量方法与采样范围。分别记录冷启动、首帧、地图生成、地貌切换、每模拟日耗时、输入延迟、缩放帧时间、内存和长时间稳定性。

延续既有目标：输入反馈 p95 尽量在 100ms 内，导航争取 60FPS、持续至少 30FPS；这些是待实测的目标，不是已达成事实。不要只报平均值，明显停顿和峰值要记录。世界容量由实际测试确定，测不出的值写不可得。

依赖沿用当前 package.json 和锁文件，有实际理由才更新。不要为了此文稿或一个轻微界面修改重装整个工具链。构建与测试不能干扰正在运行的其他验证或我的个人试玩。

### 十九 原作和网页验收场景

先固定样本与预期，再做相应实现；功能批完成后统一运行有意义的检查。下面的场景分别记录工程、浏览器、真机和用户视觉结果：

1. **手绘地图**：空白海洋 → 不对称大陆 → 宽海湾/细长海岬/岛屿 → 陆地连接 → 海笔刷切开 → 撤销重做 → 保存刷新，地图完全恢复。
2. **保形自然化**：同一大陆生成内部地形 → 对照原图 → 取消 → 重新生成并确认，海岸保护、锁区与主要连通关系符合合同。
3. **连续缩放**：全景至近景反复缩放平移，海面、岸线、河口、国界、城市与标签保持一致；没有意外重生地图。
4. **图层与文字**：地理/政治等已有图层逐一切换，原始数据不变；长名字、小岛飞地、环形领土、重叠标签可读、可选。
5. **建国与一块一城**：在手绘大陆自动建国并手改，地形不变；每块陆地辖区有真实城市，首都引用和人口资源合法。
6. **飞地与首都**：同国有三片领土 → 一片被占 → 首都失守 → 尚有领土 → 全部失守 → 复国，国名、首都标记、城市历史与实际状态一致。
7. **纯看海**：不发军令运行固定时长，观察实际发展与自主外交/战争；暂停、调速、查看原因、保存恢复均能继续同一个世界。
8. **外交与过期命令**：宣战预览后取消无变化；确认后生效；局势变动后旧预览被拒绝；停战影响行军、接敌、追击与占领。
9. **陆战闭环**：征募扣资源 → 下令 → 道路遭遇 → 伤亡 → 撤退/击溃 → 返乡重编 → 补员 → 恢复行动，账目与地图一致。
10. **攻城和抵抗**：有守军、空城、地区抵抗、补给不足等场景分别运行，确认目标、战斗、占领与日志没有矛盾。
11. **跨海与海战**：装载 → 航行 → 海战/改令/港口易主 → 登陆 → 保存刷新，不复制或丢失同一军队。
12. **王号与传位**：同号、换号、恢复旧号、另一国同号、覆亡复国后传位，两类编号和人物历史正确且可恢复。
13. **地方政治**：起义、和平独立与覆亡真实改变版图、外交和资源，事件有地点与原因；重复请求不会重复建国或重复扣人口。
