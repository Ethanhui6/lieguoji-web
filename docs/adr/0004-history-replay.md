# ADR 0004：可校验历史、只读回放与独立分支

日期：2026-09-23。M4 本批只处理三项历史能力，沿用现有自建世界与 0.1/0.2 规则。皇室人物、亲属、继承和正式史实尚未定义或实现，不推断 CANON 的未知项。正式核图与真机验收仍独立待验。

## 记录的含义

近期 160 条事件只是说明，不是完整历史。用户在自建推演的纪事内确认创建记录副本，从当前权威暂停快照开始，新 run-h 身份、独立数据库；原局与未记录的过去不改、不补造。成功的单日推进、军令、国家行动各自取得连续序号。同日多次操作不能仅按日期区分，预览、取消、失败、step:0 不记录。

HistoryLog 格式 1 包含初态、外部输入序列、每步前后 day/nextEventId/SHA-256、每 32 步完整检查点、规则版本及实现内容指纹。自主决策由原模拟重算，不伪造额外玩家输入。对象键规范化后求 hash，数组顺序保持。规则指纹取固定排序的 sim 与 history 核心源文件，统一换行；文档提交和界面改动不改变指纹。规则不匹配时保留文件、只读展示最近快照并允许导出，禁止冒充精确回放。

## 存储与故障

使用独立 IndexedDB lieguoji-history-v1。世界快照与历史同一封装、同一事务、同一 revision CAS，完整 current/backup 对恢复；旧版网页的普通 save API 不会写入此命名空间。包先复制再异步校验。所有内外未来版本先锁写，再考虑损坏恢复；不因指纹变化退回旧备份。

单历史最多 2048 条输入、20 MiB UTF-8；全历史库 current+backup 预算 200 MiB，浏览器实际配额可能更低。任何超限、事务失败或冲突都拒绝本次追加，保留原完整记录；自动推演暂停，Worker 回到已提交状态，不能显示“已保存”的未提交新日。当前界面显示实际保存状态。容量上限不自动删档。

工坊索引与历史数据库不能跨库原子提交。先建立新记录，再登记工坊；登记失败保留原局并报告新记录恢复编号，不声称创建流程完成、不删除孤立记录。

## 回放与分支

独立 replay Worker 先从初态完整重算核验，随后从最近检查点定位序号。日期定位落到当日最后一条记录。时间轴播放只改变查看位置，live Worker 保持暂停；UI 和 hook 均禁止军令、国策、保存、快照替换等写入。退出回放恢复原 live 状态，回工坊不保存回放快照。

分支预览冻结源 run 与序号，确认再次取得重算快照及 hash，并在根层核对实际源记录。新身份从选定日期开始，parent 仅记录源 run/seq/hash；后续输入只追加新分支，源历史不写。

历史文件独立 .history.json 外层格式与 checksum。导入须完整校验并通过 replay Worker 重算；保存为新 storageId 的只读归档，原历史内部 runId、输入及 hash 均保持原样。继续推演须从归档建立新分支。普通 .save.json 与 .world.json 的上限/规则保持原状，不能用普通存档覆盖记录链。

## 验收

M4-001：核心结构、确定性重算、检查点、原子存储/备份/CAS/版本/容量与旧局保护。

M4-002：桌面/手机/平板仿真的时间轴定位、播放暂停、地图与账册状态、只读护栏、退出原局字节不变、独立 Worker 与正常资源加载。

M4-003：确认/取消分支、新身份与父链、源字节不变、独立推进及刷新、历史导入导出与坏档保护，真实 CI 与实际 HTTPS 验证。移动仿真不替代真机。
