# ADR 0003：真实经营、显式外交与旧局副本

日期：2026-09-23。状态：本批设计采纳，功能状态与验收以 plan/tasks.json 为准。

## 范围与依据

世界工坊已上线，下一批以用户确认的国家经营、外交和可解释自主推演为目标，划分 M3-001、M3-002、M3-003 三项。原 v2 规划仍缺失，本文件是补缺设计，不改 CANON，也不将工程平衡参数写成正式历史统计。

## 经营与地理

人口与粮食库存落在真实辖区，国家按实际控制权汇总。粮食从地形生产，供居民消耗和驻军补给；驻军不能继续凭空无限恢复军粮。平原、森林、山地与现有城市影响规则，粮食短缺影响人口或军队，原因必须可查。

国家选择民生、均衡或军需优先，实际影响粮食分配。界面同时区分下一日估算和最近一次已结算账目：期初粮食、实际产出、居民实际消耗、军需实际消耗、期末粮食与短缺损失。第 0 日没有已发生账目，不能以预测冒充收入。

占领改变实控人口、土地和粮食归属，法理疆域与国家/政权/皇室身份保持独立；首都失守不自动灭国。隔海领土可以同国，但不能生成跨海军队道路。

## 外交与命令

新世界和平开始，每对国家只有一条规范化双边关系。寻路、命令预览、在途行动、接敌、追击、战斗、占领和军事 AI 共用和平/战争判断；不允许只限制 UI 而由模拟暗中发动攻击。

宣战和停战为玩家在沙盒中的明确干预，先预览再确认；停战不冒充单方提议被对方自动接受。预览说明战争状态、保护期与现有军令处理。停战不会瞬移部队，不改法理疆域，和平关系下不能继续伤害或占领对方。

预览携带 day + nextEventId，Worker 确认时检查版本并重新验证动作。预览后局势变化必须重做预览，取消不修改状态；操作开始暂停推演，完成后由玩家自行继续。

自主决策使用可复现的粮食、兵力、陆地邻接与外交状态，输出明确理由。无合适目标、补给不足、保护期未结束等也是可解释结果，不靠随机换色制造战争。不能覆盖已经执行中的玩家军令。

## 版本与旧局保护

- 旧 World schema 1 / rules 0.1.0 / save envelope 1 保留原样，旧战役与旧自建世界继续执行原有规则。
- 新 World schema 2 / rules 0.2.0 / save envelope 2 明确包含经营外交状态；工坊草稿与历史索引保持 schema 1。
- 不在读档时静默补字段、不自动写回。先校验原始封装与原始世界 checksum，严格接受对应版本组合；内外层未知未来版本均锁写，不回退旧备份来覆盖新数据。
- 旧自建世界可明确选择“创建经营推演副本”。保留日期、地图、军队、路径、法理/实控和事件，将新增经济参数按确定性规则初始化；旧军事规则下异国敌对，副本沿用战争关系，而非突然停掉现有战争。
- 副本使用新的 run ID 与独立数据库，原运行数据库及历史不写。新库写入成功后再登记工坊历史；失败不导航、不删除旧历史。保留并发操作锁、数量上限、revision 与原值 CAS、有效备份和跨世界导入拒绝。

## 交互与验收

桌面复用地图右侧栏，在军令与国家之间切换；国家面板提供经营和外交。手机/平板底部工具与抽屉操作，核心按钮至少 44px，不增加挤压地图的第四栏。

单元测试覆盖粮食守恒、政策分配、短缺后果、确定性、所有和平约束点、停战在途处理、无效/过期命令和双版存档。浏览器验证政策预览取消/确认、真实日结、宣战停战、保存刷新、旧局独立副本以及桌面/手机/平板操作。旧 30 项核心场景继续回归。

CI 和原生 Pages 分支预览通过后才受控合并。最终只发布 dist，并验证实际 HTTPS URL、构建 SHA、Worker、控制台、深链接和本批保存恢复。正式核图、真实手机与未知历史仍独立待验。
