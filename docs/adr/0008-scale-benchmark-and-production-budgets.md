### 独立实体实验方法

`entity-budget.ts` 的专用格式为 `lieguoji-entity-budget-component`，不能通过或放宽原 `ScaleFixture` 校验。`measureEntityBudgets` 创建标准源；已有测量源可交给 `measureEntityBudgetsForSource`，其 `sourceCreationMs:null` 表示创建成本由外层另行记录，不将未测值写成0。

基线与八个单轴高点均保留65,536地理样本、1,024模拟区和32国家。行政成员单独存于 `cellAdmin`；新增行政叶必须有实际陆地成员，层级对照为每国增加两个合法父节点，不能用空树或增加模拟区代替行政压力。城市高点增加同地理位置的聚落分点，再重映射已有群体；家族高点重映射已有人物，保证新增城市／家族有真实成员。群体高点拆分人口与粮食且总量守恒；具名人物不额外增加人口，军队高点没有声称执行真实征募。

每案分别记录创建、严格校验、索引、地理摘要、全字段摘要和逻辑字节计数的原始耗时。基线对七类关系各做256次真实关联查询，高点对相应关系做256次；查询保留结果、引用校验和、旧／新增ID覆盖。单次阶段采样不称为p95；完整摘要计时包含自身校验。每案记录目标外必要引用的新增／变更数量，发现未允许变化即失败。

源前后完整hash、各案地理hash必须一致；全字段hash包含类型数组实际字节与所有元数据。组件地理与只读标准源共享，专用Worker在transfer前必须克隆待交付组件，不能分离权威源buffer。Worker／主线程各自校验和摘要以及clone／transfer往返成本由独立补证记录，不能把纯函数单测耗时当传输测量。

组件7项和专用桥／Worker20项定向测试通过；最终 v3 整批检查为569项单元测试／24文件、14项发布门检查、23项生产产物检查通过。真实实体报告另证明九案地理摘要一致、源前后摘要相等、54个交付样本的主线程／Worker／初始组件完整摘要一致。单次阶段统计的 p95 保持 null。真实往返范围为391.1—828.3 ms，包含组件创建、校验、摘要、准备及交付；主线程收包后的校验和摘要另计，不能称为纯 IPC。

标准大陆的三次 clone round trip 为 638.5—684.1 ms，三次 transfer 为 674.0—784.7 ms；载荷 3,434,179 bytes。这里包含 Worker 摘要、逻辑字节计算、准备与传输，不是纯 structured-clone 时间；`prepareMs` 本身约 518.8—660.0 ms。因此不能宣布 transfer 自动更快，也不能把测量器计数成本误归为浏览器复制成本。

同景首存 412.1 ms，带备份再存 668.6 ms；一次当前档恢复的读取为 1,094.7 ms、核验与载入为 1,745.9 ms。它们是该场景早期短记录的真实单次值，**不是 512／2048 记录存读档数据或 p95**。

结论是先去掉无条件的整世界传输、序列化和反复全静态数据校验。不得为提速删 hash、弱化校验、绕过持久化失败或修改旧引擎上限。

## 5. PH04 生产模型与 owned 增量校验

生产采用新的 manifest／块格式和独立数据库，不将 `ScaleFixture`、合成人物或结构日结核直接导入游戏。旧 `World`、0.4 冻结闭包、旧数据库与历史上限保持不变。

权威层明确分离：共享地理几何、地块→模拟区、地块→行政叶、行政父树、法理归属、实际控制、动态社会状态。行政成员不能被模拟区一对一映射永久限制；上级覆盖、面积与索引由权威成员派生。

逻辑块 ID 绑定 atlas 身份／拓扑版本／层／块坐标；内容 hash 标识该次不可变块。边界共享顶点唯一归属，邻块只持引用或派生显示缓存。细分／合并创建新 ID 与沿革，不复用旧身份。

外部导入／恢复先做完整格式、引用、块 hash、根引用及规则兼容核验。只有 Worker 独占的已核验会话才允许增量路径：事务明确读写集合与 base revision，复制受影响块，核验新块及受影响跨块引用，重新计算脏块 hash 和根摘要。

不以 `Object.freeze(typedArray)` 冒充不可变，也不对外部可变 raw 对象缓存验证结果。主线程收到渲染副本，transfer 不分离权威缓冲区；每次导出／恢复和固定审计点仍能完整核验，与增量根 hash 一致。

内容块可预写，只有完整校验、容量和 CAS 通过后才原子切换 current／backup／目录／容量账目。候选失败不发布成功 delta；取消不得提交半成品，提交后的撤销是下一笔事务。版本未知的主档或备份均锁写，临时块清理不删除已引用玩家历史。

存储生产目标为：标准档2048输入的current＋backup＋保留日志／索引可达逻辑数据≤128 MiB；10,000日长局≤512 MiB。后继验收仍需补齐真实规则数据、保留策略、暂存上限、压缩前后大小和真实配额故障；不能只凭原型39.933 MiB主备包判定通过。它们不提高旧历史v1的20 MiB日志／200 MiB全库上限，也不授权自动删除玩家历史。

长局内存不先给“真机可用”数字。记录可获得的主线程／Worker／进程／GPU指标各自来源；可比静止检查点的主线程样本中位数，末5分钟相对首5分钟增长目标不超过 `max(16 MiB,10%)`，同时记录实体增长。缺失 Worker／GPU／整进程指标时，这只能说明主线程样本，不能证明无全局泄漏。
