# PH03 大世界规模实测方法

本文记录本地结构原型的方法，实际结果和设备合同在测量完成后另附证据。原型不属于正式游戏、不兼容游戏存档；原型中的结构日结不能替代后续人口、物流、家族、信仰及战争规则。

## 样本与可重复性

种子固定为 `ph03-repeatable-001`，生成版本 `ph03-structure-v1`；同一 4096×4096 世界范围，在 128²、256²、512² 地理采样上生成大陆、群岛、山地三种场景。共享扰动顶点定义真实可编辑四边形，连续场生成海陆、高程和湿度。地理分辨率与实体档独立，不把地块数称为行政单位数或人口数。

| 实体 | 基础 | 标准 | 扩展 |
| --- | ---: | ---: | ---: |
| 地理采样 | 16,384 | 65,536 | 262,144 |
| 模拟区 | 256 | 1,024 | 4,096 |
| 国家 | 16 | 32 | 64 |
| 城市 | 512 | 2,048 | 8,192 |
| 人口群体 | 4,096 | 16,384 | 65,536 |
| 具名人物 | 2,048 | 8,192 | 32,768 |
| 家族 | 256 | 1,024 | 4,096 |
| 组织 | 64 | 256 | 1,024 |
| 军队 | 64 | 256 | 1,024 |

行政叶单位与模拟区数量相同，但通过单独 ID 引用；国家采用 1—4 层树，父级另外计数。城市→模拟区→当前行政单位→国家以及人物→群体→城市、人物→家族、组织→成员、军队→驻地均为有效引用。各档同时生成这些实体后测量，不能把独立上限拼为联合支持承诺。

## 执行与证据

`npm run bench:build` 使用独立配置，在 `.autopilot/ph03/web` 构建实验入口。`npm run bench:preview` 仅绑定 `127.0.0.1:4174`。`npm run bench:measure -- --mode=…` 通过本机 Chromium 运行实际 Pixi、Worker 和 IndexedDB，不写游戏数据库、不访问云端。生产 `dist` 和 Pages 入口不包含实验台。

每次运行生成独立带时间戳目录，保留失败和后续修复记录。报告包含本地提交、全部实验源码摘要、冻结引擎摘要、原始硬件清单、真实浏览器版本和 WebGL renderer。脚本拒绝源码与构建摘要不一致。每步完成立即写入原始 JSON；图表与汇总须能追溯这些原始值。

- `smoke`：基础大陆短路径，用于检查实验链路，不算 60 秒持续帧率证据。
- `matrix`：三档联合负载×三种地理场景，每项真实 60 秒固定镜头路径；生成两次核对完整摘要，继续编辑、撤销、改隶、传输、主备保存、刷新恢复、只读历史及独立分支，并测试 64 条结构历史。
- `controls`：标准/扩展地理配基础实体、基础地理配标准/扩展实体，识别地理与实体负载差异；不作为全部高负载同时支持的证据。
- `history --profile=…`：指定联合档测 64/512/2048 条结构记录，覆盖 32 条间隔检查点边界、完整重算、定位及独立分支。
- `entities`：固定标准地理及其他基准实体，对行政数量/深度、城市、群体、人物、家族、组织和军队做分别变化的对照。使用独立组件实验格式，不放宽联合样本校验；必要引用重映射和守恒分别记录。另测这些真实组件的主线程校验以及 clone/transfer 往返。
- `mobile`：标准联合档在 Pixel 7 参数下执行相同流程，属于桌面 Chromium 的移动仿真，不能写成 Android 或 iOS 真机验收。
- `guards`：实际 IndexedDB 读取和 Worker 快照等待时取消，验证不会稍后替换会话或创建存档；在独立实验的选择重绘处注入故障，确认后续修改/保存被锁定，刷新后完整原主备包装不变。这是功能边界验证，不是性能档。

每项首次生成与同页重复生成分别记录；首次页面初始化单列。操作系统文件缓存和 GPU 驱动缓存没有强制清空，所以不能称为机器冷启动。性能期间只运行一项浏览器负载，避免并行基准互相争抢资源。

## 指标口径

固定镜头路径连续记录全部 `requestAnimationFrame` 间隔和主线程绘制提交耗时，报告 p95、最大值、均值、样本数、实际持续时间、可见块/标记/标签数。绘制提交耗时不等于 GPU 完成时间。页面隐藏、取消、浏览器错误和不足持续时间均不能作为有效性能通过。高低画质只能改变像素密度、边界细节与标签数量，须验证同一屏幕位置指向同一稳定对象、权威状态不变。

正式采样使用完整 Chromium 的 headless 模式，实际 WebGL 已核实为 RTX 3060 / D3D11。headless 的帧回调可能不受显示器刷新率限制，因此不能把回调数直接写成真实屏幕 FPS；画面验收和正式游戏全视口流畅度仍须在 PH05/PH35 的实际入口验证。报告保留真实 Canvas 视口尺寸，不能拿实验侧栏挤出的较小视口冒称全屏测量。

线程计时拆为权威计算/哈希、传输准备、主线程往返；比较原生 clone 和克隆后 transfer。为了保留权威缓冲区，transfer 先复制再转移，该成本必须计入，不能宣传为零拷贝。当前全量快照只是 PH03 比较基线，PH04 必须改为有界增量消息。

结构批次只做合成群体的确定性产出/消耗；保存规则包括全部字段和 TypedArray 原字节摘要，不能跳过校验换取漂亮数字。当前保守历史追加会重新扫描整个历史格式及检查点，报告中必须指出随历史增长的重复扫描成本，不能把它当作硬件容量限制。PH04 的内部权威结构应通过受控增量验证避免重复扫描，外部导入仍完整核验。

隔离数据库为 `lieguoji-scale-bench-v1`。主档、上一份备份和 revision 同一事务提交，恢复前完整核验历史。报告存储层定义的逻辑载荷字节，不将其等同于 IndexedDB 物理占用；测主备同时保留时的逻辑增长。CDP 每 5 秒采样主页面堆，Worker/GPU/整个浏览器的峰值不可由该指标推断；取不到的峰值明确为未知。

专门长历史模式将每个长度写入新隔离 UUID，两次相同包形成真实主备并明确该备份语义；分别读取并完整重算主备。对完整 current/backup/revision 包在追加或独立分支前后求摘要，证明源记录未改。runner 随后逐个刷新文档、重新创建 Worker 再恢复核验，不能仅凭内存 byteSize 或同进程重开 IDB 声称刷新恢复已测。

控制器取消必须覆盖主线程的等待阶段，不能只向当前可能空闲的 Worker 发取消。存储写事务开始前检查取消；开始后以真实事务complete/abort结果报告，不声称取消已经提交的写入。渲染接受涵盖setFixture和选择恢复；权威线程已经完成但任一画面接受步骤失败时，控制器锁定后续操作，刷新恢复已保存状态。修复版本须单列源码指纹与定向验证，先前正常路径的测量不冒称已经覆盖后来发现的故障路径。

桌面 60 FPS、移动持续 30 FPS 的产品目标保持不变。实测未达目标的场景须记录差距并给后续架构/规则阶段设约束，不能降低标准 65,536 地理目标，也不能悄悄减少存档内人口、行政和规则。真实 iOS/Android 设备、长期完整规则和最终用户视觉验收分别留给 PH33/PH35。
